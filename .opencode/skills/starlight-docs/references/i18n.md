# 双语配方（i18n）

默认单语言。双语是**显式可选**：`--locales root,zh-cn`。

## 1. 三种「语言代码」不要混

| 用途 | 取值 | 例子 |
|---|---|---|
| Starlight locale key（URL 段） | 小写、可带连字符 | `root`、`zh-cn` |
| sidebar `translations` 的 key | BCP-47 | `zh-CN` |
| `<html lang>` | BCP-47 | `en`、`zh-CN` |

`root` 是默认 locale 在配置里的**名字**，不是语言代码；它的 `lang` 才是 `en`（或你指定的值）。
scaffold 会把常见 key 映射成合适 label 与 `lang`（`zh-cn` → 简体中文 / `zh-CN`），不认识的 key 原样使用。

## 2. 首次访问不嗅探语言

- 默认访问 `/`（root locale），**禁止** `navigator.language` / `navigator.languages` / `accept-language` 跳转。
- `check` 会扫构建里的 HTML 与 JS，命中即 `LANGUAGE_SNIFFING`（error）。
- 想「记住用户上次选择」是可以的，但那是存 locale 偏好后由**用户动作**触发，不是首屏自动跳。

## 3. 切换器必须映射到同一 slug

`LanguageSelect.astro`（scaffold 多语言时生成）是链接列表：

- 当前语言由触发器文字表示，列表里不再多一种「选中底色」；
- 每一项指向**同一 slug 的另一种语言**：`/actions/list/` ↔ `/zh-cn/actions/list/`；
- `check` 对每个页面、每个其他 locale 检查这个链接是否存在，缺了报 `SWITCHER_MISSING`。

如果手工改成 `<select>` 或别的结构，**检查脚本不会自动跟着变**：要么保持链接式，要么接受 `SWITCHER_MISSING`。v1 生成的组件就是链接式。

## 4. parity 的边界（core 的一部分）

`check` 只做轻量镜像，不做翻译质量判断：

- **页面集合**：root 与每个 locale 的路由集合必须互为镜像（`ROUTE_MIRROR_MISMATCH`）。
- **必填键**：每页要有 `description`（渲染成 meta description），缺了报 `DESCRIPTION_MISSING`；每页恰好一个 `<h1>`。
- **标题数量**：同上，`H1_MISSING` / `H1_MULTIPLE`。
- 不做：全文语义比对、段落数量、链接文案一致性。

## 5. 新增一个语言（手工步骤）

1. 在 `astro.config.mjs` 的 `locales` 加一项：`'ja': { label: '日本語', lang: 'ja' }`；
2. 按现有结构镜像内容目录：`src/content/docs/ja/**`（`index.mdx` + 每个页面）；
3. 若用 `LanguageSelect`，确认 `--components theme+lang` 已生效（组件本身读 `config.locales`，不用改）；
4. sidebar 的 `translations` 按需补：`{ 'ja': '...' }`；
5. 重跑 `check`：路由镜像、`lang`、切换器三项必须全绿。

## 6. 常见失败

| 症状 | 原因 | 处理 |
|---|---|---|
| `ROUTE_MIRROR_MISMATCH` | 某一语言缺页/多页 | 补齐或删除，保持一一对应 |
| `SWITCHER_MISSING` | 切换器只链了部分页面，或手写 `<select>` 少了选项 | 用生成的组件，别手改结构 |
| `LANG_MISMATCH` | 某页 `lang` 与同语首页不同 | 检查 `locales.<key>.lang` 与内容目录归属 |
| `LOCALE_HOME_MISSING` | 有 locale 但没 `<locale>/index.*` | 补一页首页 |
| `LANGUAGE_SNIFFING` | 主题/分析脚本里做了语言跳转 | 删掉跳转或改为用户动作 |
