# v1.1.0 发布说明（中文）

> 本文件是 GitHub Release `v1.1.0` 正文的中文版。**Release 正文只放英文**，这里只进仓库 / 文档站，
> 不追加进 Release（见 `AGENTS.md`「发布（Release）」）。

## 这是什么

`skill_management` 给 OpenCode 里已安装的 skill 装一个开关：看清装了什么、某个 skill 为什么加载不了、
把它从模型视野里拿掉、再放回来。

停用**不碰任何 skill 文件**：只在全局配置里写**一条** `skill` 权限规则（`effect: "deny"`，
软停用用 `"ask"`）。删除、移动、改写 skill 文件都不做；删掉那条规则，skill 就回到原样。

## 1.1.0 有什么变化

**破坏性变更：四个动作的输出从 Markdown 改成单个 JSON 对象。**

- 工具现在声明 `output` JSON Schema，宿主会按它校验结果。这是真正的结构化工具结果，不是把
  Markdown 塞进一个 JSON 字符串。
- 公共信封：`schemaVersion`（当前 `1`）、`action`、`ok`、`warnings`。失败时 `ok: false`，
  并带 `error: { code, message }`，不再靠正文里的 ✅ / ❌ 判断成败。
- `list` 返回 `callerAgent`、`summary`、`skills[]`、`config`、`sidecar`、`consistency`；
  `description` 仍只取首行，但不再截断到 60 字符。
- `inspect` 返回 `skill`、`idDerivation`、`agents[]`、`caller`、`conclusion`；找不到与重名分别用
  `skill_not_found` / `name_ambiguous` 表示。
- `disable` / `enable` 返回 `changed`、`reason`、`before`、`diff`、`verification`、`backup`、
  `sidecar`；`enable` 另有 `location`、`rule`、`candidates`、`relatedRules`。
- `enable` 在目标配置无法解析且没有候选规则时，改为 `ok:false` + `config_unparsable`，
  不再把「读不到」说成「无需修改」。

除此之外没有破坏性变更：动作、入参、写入的规则形状、行尾标记格式与单文件结构都没变。

## 四个动作

| 动作 | 做什么 | 写配置 |
|---|---|---|
| `list` | 列出所有已注册 skill，以及它们**对当前调用者 agent** 的有效状态（`available` / `disabled` / `ask`） | 否 |
| `inspect` | 查单个 skill 为什么（不）可用：命中的是哪条规则、各 agent 的差异、id 是怎么来的 | 否 |
| `disable` | 让它从模型可见列表里消失、并拒绝加载（`effect: "ask"` 则保留在列表里、加载时确认） | 是 |
| `enable` | 删掉挡路的那一条规则，恢复可用（不要求是本工具写的） | 是 |

权限按**发起调用的那个 agent** 的规则集求值：最后一条命中算数（`findLast`，支持 `*` / `?`），
**一条都不命中时回退 `ask`，不是 `allow`**。

`disable` 写进去的就是这一行（行尾注释是来源标记，`enable` 靠它定位）：

```jsonc
{ "action": "skill", "resource": "windows-shell", "effect": "deny" } // skill_management
```

## 怎么用

```text
skill_management({ action: "list" })
skill_management({ action: "inspect", id: "windows-shell" })
skill_management({ action: "disable", id: "windows-shell" })
skill_management({ action: "disable", id: "windows-shell", dryRun: true })
skill_management({ action: "disable", id: "windows-shell", effect: "ask" })
skill_management({ action: "enable",  id: "windows-shell" })
```

`list` 的返回大致长这样：

```json
{
  "schemaVersion": 1,
  "action": "list",
  "ok": true,
  "warnings": [],
  "callerAgent": { "id": "build", "verified": true },
  "summary": { "total": 29, "disabled": 1, "ask": 0, "diverged": 2, "derivedIds": 0 },
  "skills": [
    { "id": "windows-shell", "state": "available", "source": "config", "path": "…" },
    { "id": "pdf-tools", "state": "disabled", "source": "catalog", "path": "…" }
  ],
  "config": { "file": "…/opencode.jsonc", "hadPermissions": true, "notes": [] },
  "sidecar": { "file": "…/skill_management.state.json", "ok": true, "error": null },
  "consistency": { "staleSidecarIds": [], "unrecordedRules": [], "missingFromRegistry": [] }
}
```

字段全集与错误码见文档站四个动作页。

## 怎么下载

| 方式 | 命令 / 文件 | 说明 |
|---|---|---|
| **npm（推荐）** | `opencode plugin add opencode-skill-management@1.1.0` | 一条命令装包并登记到全局配置；不需要 token |
| git spec | `opencode plugin add github:sogeisetsu/opencode-skill-management` | 不走 npm 注册表 |
| 单文件插件 | 附件 `skill_management.js` | 放进 `<config>/plugins/` 即可；离线 / 无 npm 时首选 |
| npm tarball | 附件 `opencode-skill-management-1.1.0.tgz` | 与 npm 上同一个 tarball；供自行解包 / 内网镜像 |

装完在**新进程**里确认：

```pwsh
opencode plugin list --builtin
# skill_management   1.1.0   opencode-skill-management@1.1.0
```

## 兼容性与验收

- 适配 OpenCode V2；1.1.0 在宿主 **2.0.32** 上完成验收（Windows + Linux）。
- `node tools/verify.mjs`：**260 项断言**全过，全部跑在临时配置目录。
- 新进程真实宿主实测：`list` 与「找不到 skill」的错误分支都返回可解析的 JSON，且通过宿主
  `output` 校验。
- 单文件、纯 Node 内置模块、无第三方依赖、不调用 shell。
