# v1.2.0 发布说明（中文）

> 本文件是 GitHub Release `v1.2.0` 正文的中文版。**Release 正文只放英文**，这里只进仓库 / 文档站，
> 不追加进 Release（见 `AGENTS.md`「发布（Release）」）。

## 这是什么

`skill_management` 给 OpenCode 里已安装的 skill 装一个开关：看清装了什么、某个 skill 为什么加载不了、
把它从模型视野里拿掉、再放回来。

停用**不碰任何 skill 文件**：只在全局配置里写**一条** `skill` 权限规则（`effect: "deny"`，
软停用用 `"ask"`）。删掉那条规则，skill 就回到原样。

## 1.2.0 修好了什么

这一版没有破坏性变更：动作、入参、JSON 输出信封、写入的规则形状、行尾 marker 与单文件结构都没动。

- **`list` 不再每次都报「N 个 skill 状态不同」。** `summary.diverged` 以前把 `title` / `summary`
  这类内部 agent 也算进去，而它们自带 `{*,*,deny}`，真机上等于每个 skill 都算「不同」（实测 33/33），
  于是每次 `list` 都带一条噪音警告。现在只统计可见 agent；`inspect.agents[]` 仍列全部，明细不丢。
- **frontmatter 的布尔值不再自相矛盾。** `disable-model-invocation: "false"` 是字符串，
  `Boolean("false") === true`，所以 `inspect` 把它报成 `true`，而 `list` 的 `autoinvoke` 是 `false`。
  现在 `true/yes/on/1` 与 `false/no/off/0`（含引号形态）统一归一，两处输出结论一致。
- **sidecar 写入失败不再把成功的配置改动报成失败。** 配置已经写入并通过回读校验后，sidecar
  落盘失败原本会变成 `internal_error`：配置真的改了，返回里却没有 `changed` / `diff`。现在返回
  `ok: true` + `changed: true`，保留 `diff`，`sidecar` 为 `null`，`warnings` 说明原因；配置不回滚。
- **`enable` 不再被无关文件的语法错误挡住。** 它会把 sidecar 记录过的其它配置文件一起读；
  以前只要其中任意一个解析失败、又没有候选规则，就报 `config_unparsable`。现在硬拒绝只在
  **目标配置文件**无法解析时触发，其它文件只进 `warnings` 并点名。

## 自 v1.1.0 以来的其它变化

- **安装器先检测再写**：`opencode.json(c)` 的 `plugins` 里已有本包、或 `plugins/` 里已有第二份副本时，
  拒绝写入并退出 `2`，一个字节都不动（双来源会让宿主报 `Duplicate plugin ID`，其中一份加载失败）。
- 安装器新增 `--check` / `--dry-run`、`--uninstall`（只删本插件那一个文件）、`--npm`（断言走 npm
  渠道）、`--force`（逃生口）、`--json`；`<config>` 解析与宿主一致（`$OPENCODE_CONFIG_DIR` 优先）。
- 插件源码新增 `export const PLUGIN_VERSION`，与 `package.json` 的 `version` 由验收断言一致。
- 验收脚本从 260 项增加到 **326 项**，并新增按 `output` schema 的逐字段校验（必需字段、属性类型、
  `error.code` / `error.message`，以及 `content` 与 `output` 是同一份数据）。
- README 精简到 51 行，字段表、安装 flags、npm 包内容、用法与验收分别落到文档站。
- 文档站新增 **Design decisions**（设计取舍：为什么写 permissions 而不是 policies、为什么没有
  allow、为什么只写全局、为什么最小文本编辑 + 同行标记、sidecar 只当审计，并写明各自代价）与
  **Development & verification**（验收分段、CI、性能与发布闸门、npm 包内容、双来源症状）两页；
  **Permissions** 的 Effects 扩成 `deny` 与 `ask` 的对比表，配三个真实 skill 例子。
  中英双语同步。

## 四个动作

| 动作 | 做什么 | 写配置 |
|---|---|---|
| `list` | 列出所有已注册 skill，以及它们**对当前调用者 agent** 的有效状态（`available` / `disabled` / `ask`） | 否 |
| `inspect` | 查单个 skill 为什么（不）可用：命中的是哪条规则、各 agent 的差异、id 是怎么来的 | 否 |
| `disable` | 让它从模型可见列表里消失、并拒绝加载（`effect: "ask"` 则保留在列表里、加载时确认） | 是 |
| `enable` | 删掉挡路的那一条规则，恢复可用（不要求是本工具写的） | 是 |

权限按**发起调用的那个 agent** 的规则集求值：最后一条命中算数（`findLast`，支持 `*` / `?`），
**一条都不命中时回退 `ask`，不是 `allow`**。

`disable` 写进去的就是这一行（行尾注释是来源标记，`enable` 靠它定位）：

```jsonc
{ "action": "skill", "resource": "windows-shell", "effect": "deny" } // skill_management
```

## 怎么用

```text
skill_management({ action: "list" })
skill_management({ action: "inspect", id: "windows-shell" })
skill_management({ action: "disable", id: "windows-shell" })
skill_management({ action: "disable", id: "windows-shell", dryRun: true })
skill_management({ action: "disable", id: "windows-shell", effect: "ask" })
skill_management({ action: "enable",  id: "windows-shell" })
```

字段全集与错误码见文档站四个动作页。

## 怎么下载

| 方式 | 命令 / 文件 | 说明 |
|---|---|---|
| **npm（推荐）** | `opencode plugin add opencode-skill-management@1.2.0` | 一条命令装包并登记到全局配置；不需要 token |
| git spec | `opencode plugin add github:sogeisetsu/opencode-skill-management` | 不走 npm 注册表 |
| 单文件插件 | 附件 `skill_management.js` | 放进 `<config>/plugins/` 即可；离线 / 无 npm 时首选 |
| npm tarball | 附件 `opencode-skill-management-1.2.0.tgz` | 与 npm 上同一个 tarball；供自行解包 / 内网镜像 |

装完在**新进程**里确认：

```pwsh
opencode plugin list --builtin
# skill_management   1.2.0   opencode-skill-management@1.2.0
```

## 兼容性与验收

- 适配 OpenCode V2；1.1.0 在宿主 **2.0.32** 上完成验收（Windows + Linux）。
- 1.2.0 在宿主 **2.2.0**（Windows）上用新进程复核：`list` / `inspect` / `disable` / `enable`
  顺序调用，写入后 `enable` 把配置文件逐字节还原，结果都通过宿主的 `output` 校验。
- `node tools/verify.mjs`：**326 项断言**全过（A–J），全部跑在临时配置目录。
- CI 在 `ubuntu-latest` 与 `windows-latest` 上跑同一套断言，不需要 secret。
